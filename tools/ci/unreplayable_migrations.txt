# Migrations that cannot be applied to an empty database.
#
# **This file is a debt register, not a permission slip.** Every line is a
# migration whose assertions are written against production data — eight runs
# computed by a particular scorer, a flag that is false in production, a likes
# table with rows in it — so replaying the chain from empty raises before the
# migration's own DDL commits.
#
# It exists because `tools/replay_contracts.sh` applied 64 of 133 migrations
# while its own comment said "the whole chain", and that silence was worth more
# than the noise: the iOS envelope check was asking a schema 69 migrations
# stale and passing, and only stopped passing when `outlook_calendar` arrived
# in 0133 and was reported as an action the schema does not weigh.
#
# The replay applies everything, continues past anything listed here, and
# **fails if a migration not on this list fails** — so the debt cannot grow
# quietly. Deleting a line when its migration is fixed is the point; adding one
# should be a deliberate act with a reason beside it.
#
# **The list is empty, and that is the state to keep it in.** Thirteen entries
# were paid off on 2026-08-13. Two were root causes and eleven cascaded from
# them:
#
#   0092  demanded that eight runs computed by scorer 0.1.0 exist. It now
#         counts them before retiring the model and asserts the count did not
#         change, which is what "retirement must not orphan them" means and is
#         answerable without knowing the number. 0094, 0109, 0110 and 0114 all
#         reported "expected exactly one active scorer, found 2" purely because
#         0092 had not retired the old one.
#
#   0102  called `pg_get_functiondef` in a `where` clause beside the filter
#         that was supposed to narrow it to schema `api`. That function *raises*
#         on an aggregate, Postgres does not promise clause evaluation order,
#         and on a fresh database the planner reached `pg_catalog.array_agg`
#         first. A latent non-determinism that production survived by the luck
#         of one plan; fixed with an `offset 0` fence. 0103, 0120, 0121, 0125
#         and 0127 followed from `assert_surface_allowed` never being rewritten.
#
#   0128 and 0132 named production's own contents — "155 rows opened", "one
#         like, declined". Both now assert against what they found rather than
#         against what one database happened to hold.
